## 🔐 セキュリティアーキテクチャ

### 多層防御 (Defense in Depth)

#### Layer 1: ネットワークレベル
- **WAF (Web Application Firewall)**
  - SQLインジェクション対策
  - XSS（クロスサイトスクリプティング）対策
  - レート制限（DDoS対策）
  - 地理的制限（オプション）

#### Layer 2: VPCレベル
- **VPC分離**
  - Public Subnet: ALB、NAT Gateway
  - Private Subnet: ECS Fargate、RDS
  - インターネットへの直接アクセス不可
  
- **セキュリティグループ**
  - 最小権限の原則
  - ステートフルファイアウォール
  - ソース/ターゲット別の詳細な制御

```
┌─────────────────────────────────────────────────────────┐
│  セキュリティグループ構成                                 │
├─────────────────────────────────────────────────────────┤
│  ALB-SG          → インターネットからHTTP/HTTPS許可     │
│    ↓                                                    │
│  ECS-SG          → ALBからのみアクセス許可              │
│    ↓                                                    │
│  RDS-SG          → ECSからのみ3306ポート許可            │
│    ↓                                                    │
│  Lambda-SG       → RDSへのアクセス許可                  │
└─────────────────────────────────────────────────────────┘
```

#### Layer 3: アプリケーションレベル
- **Secrets Manager**
  - RDS認証情報の暗号化保存
  - 自動ローテーション（30日周期）
  - アプリケーションからの動的取得

- **IAMロール**
  - タスクロール: コンテナからAWSサービスへのアクセス制御
  - 実行ロール: ECSがECR、CloudWatch Logsにアクセスするための権限

#### Layer 4: 監視・検知
- **GuardDuty**: 異常な動作の検知
- **CloudTrail**: すべてのAPI操作をログ記録
- **IAM Access Analyzer**: 過剰な権限の検出
- **VPC Flow Logs**: ネットワークトラフィックの監視

```
│  - トークン検証                                               │

                    ▼
```

- ✅ IAMユーザーのアクセスキー不要
- ✅ 認証情報の漏洩リスク低減
- ✅ 一時的な認証情報（短い有効期限）
- ✅ より細かいアクセス制御

## 📈 スケーラビリティ

### 水平スケーリング

#### ECS Fargate Auto Scaling

```hcl
# CPU使用率ベースのスケーリング
Target Tracking Policy:
  - Metric: CPU使用率
  - Target: 70%
  - Min Tasks: 2
  - Max Tasks: 10
  - Scale Out: CPU > 70% → タスク追加
  - Scale In: CPU < 70% → タスク削減（5分間のクールダウン）
```

#### Aurora Read Replica Auto Scaling

```hcl
# 接続数ベースのスケーリング
Target Tracking Policy:
  - Metric: DatabaseConnections
  - Target: 100接続
  - Min Replicas: 1
  - Max Replicas: 3
  - Scale Out: 接続数 > 100 → Reader追加
  - Scale In: 接続数 < 100 → Reader削減
```

## 💰 コスト最適化戦略

### コスト配分（月額）

```
dev環境（$100-150）:
├── Aurora MySQL (1台)         $50-70   (47%)
├── NAT Gateway (1台)          $35-40   (30%)
├── ECS Fargate (2タスク)      $10-20   (13%)
├── ALB                        $20-25   (17%)
└── その他 (Logs, S3, Lambda)   $5-10    (7%)

prod環境（$350-500）:
├── Aurora MySQL (3台)        $150-210  (50%)
├── NAT Gateway (3台)         $105-120  (30%)
├── ECS Fargate (4タスク)      $20-40   (10%)
├── ALB                        $25-30    (7%)
└── その他 (Logs, S3, Lambda)  $10-20    (4%)
```

### コスト削減施策

1. **環境別リソース最適化**
   - dev: 単一AZ、最小インスタンス
   - stg: 2AZ、中程度のインスタンス
   - prod: 3AZ、本番相当のインスタンス

2. **非稼働時の停止**
   ```bash
   # 夜間・週末のdev環境停止
   aws ecs update-service \
     --cluster srep1-dev-ecs-cluster \
     --service srep1-dev-front-nginx-service \
     --desired-count 0
   ```

3. **Fargate Spot活用**（dev/stg環境）
   - 最大70%のコスト削減
   - 中断許容可能なワークロードに最適

4. **S3ライフサイクル設定**
   - 30日後にIntelligent-Tieringへ移行
   - 90日後にGlacierへアーカイブ

5. **CloudWatch Logsの保持期間最適化**
   - dev: 7日
   - stg: 14日
   - prod: 30日

```
│  GuardDuty         脅威検知イベント                          │
│  IAM Access Analyzer  アクセス権限の分析                     │
└─────────────────────────────────────────────────────────────┘
```

### データ保護

- **暗号化**
  - 転送中: TLS 1.2以上（ALB）
  - 保存時: AES-256（S3, EBS, RDS）
  
- **アクセス制御**
  - IAMポリシーによる最小権限
  - セキュリティグループによる通信制限
  - Secrets Managerによる認証情報保護
